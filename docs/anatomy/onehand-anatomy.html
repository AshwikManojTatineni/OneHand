OneHand (code name xbody-bench) is a zero-training benchmark: can a robot policy or a classical controller built for the 7-joint Franka Panda work on the 5-joint SO-101 when the only adapters allowed are kinematics, calibration and test-time search? This report reads the code layer by layer. Part I is the shape of the whole codebase; Part II goes file by file and function by function, with the mathematics each function implements.

Part I. The codebase as a graph

The repository has 52 Python modules, 7 shell grids and 3 YAML files (6,822 lines, 323 functions), plus 9 Markdown documents. The import graph has 102 edges. Fig 1 draws every file as one block on a bench: the block's height is its line count, the studs on its top are its functions and the rings its classes, and its station is its layer.

LayerFilesRole
Core library7Body specs, interface K (IK), scene builder, staged scorer, statistics, frozen-policy loader, calibration errors. Everything else imports it: stats has 14 importers, bodies 13, kinematics 11, scene 10.
Classical stack8The nine-layer S1 pipeline: perception, world model, endpoint IK, planning, timing, tracking, conversion, control, actuator.
Self-model9Product-of-exponentials identification from teleop logs, the sensor lab (mono, stereo, lidar) and the experiments that use them.
Evaluation scripts14Command-line evaluations, Phase 0 checks and summarizers that write results/*/SUMMARY.md.
Grid orchestration7Shell loops that sweep the evaluation scripts over bodies, interfaces and methods.
GPU routes7MJX and Isaac Lab ports of the task with PPO trainers. Written, never run here.
Protocol and registry3The frozen protocol and the checkpoint registry.
Docs and results9README, RESULTS and the generated summaries.

Edges between layers (imports, triggers and dependencies): evaluation → core 32, self-model → core 15, grid → evaluation 8, evaluation → classical 8, classical → core 7, everything else 1 to 4. The graph is a clean stack: the core library imports nothing from the layers above it (its one upward edge is calibration importing selfmodel_diff), and the classical stack depends only on the core.

One classical episode (Episode.run) runs the layers in this order:

  1. Perceive: render depth from the scene and wrist cameras, back-project, remove the robot, fit the cube, cluster obstacles.
  2. Build the world model (octomap, voxel, ESDF, TSDF, mesh, primitives or pose).
  3. Solve four endpoints (pre-grasp, grasp, pre-place, place) for each of four grasp yaws and keep the best scored set.
  4. Plan home → pre-grasp, then pre-grasp → pre-place with the cube attached; shortcut both paths.
  5. Time each path within the body's velocity, acceleration and jerk limits.
  6. Track the timed reference with the chosen joint or task-space law, converting task twists to joint rates where needed.
  7. Score every physics step with the shared staged scorer (reach, grasp, lift, transport, place).
