The robots: MJCF, not URDF

There is no .urdf because this project never uses URDF for the two arms. It loads MuJoCo's own format, MJCF (.xml), from Google DeepMind's MuJoCo Menagerie: franka_emika_panda/panda.xml and robotstudio_so101/so101.xml (xbody/bodies.py, SPECS[...]['xml']). The README tells you to clone them into assets/mujoco_menagerie/, and .gitignore excludes that folder, so they were never in the repository. That is why you could not find them. I cloned them for this audit; the drawings and tables below are read from those files, not typed in.

Route B is different: it uses ManiSkill's built-in Panda, SO100 and xArm6, which ManiSkill loads from its own URDF assets at run time. Those are not in this repository either, and the SO100 is an older sibling of the SO-101, not the same arm.

Two of these matter for reading the results. Route B scores with its own 0–4 stage rules, not the protocol's 0–5 scorer, so a route B 'mean stage' and a classical 'mean stage' are on different scales and should not be compared. And the three ways of making a 'real' arm use different error models, so the teleop pilot, the sensor study and the task study each test a slightly different arm.

What the results do and do not show

  • Everything is simulation. No physical robot, no recorded hardware data. The 'real arm' in every self-model study is the same CAD model with random offsets added in code (perturb, real_robot, build). The results say how methods behave against those synthetic errors, not on a real SO-101.
  • The results are genuine simulation output. The ones I could re-run reproduce, the summary matches the raw files, and the git history shows long runs committed by an automated agent with periodic auto-saves (2026-11-01 to 11-02). I found nothing fabricated.
  • Route B's SO-101 is really an SO100, ManiSkill's model, and it scores with its own stage rules.
  • Sample sizes are below the protocol. protocol.yaml asks for 50 screening and 200 final episodes per cell; the classical grid ran 20 (10 for MPC, NMPC, LQG). The protocol is still marked frozen: false.
  • The teleop pilot's sensor is an oracle (true pose plus Gaussian noise). The sensor-swap study replaces it with real perception pipelines on rendered images; that is the more credible of the two.
  • A ground-truth leak existed in the mesh world model (fixed in 0e6d802). No stored cell combined mesh with a perturbed arm, so no published number was affected, but it shows the belief/real split needs care.
